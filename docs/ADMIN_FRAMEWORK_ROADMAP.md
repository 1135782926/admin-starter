# 通用后台框架路线图

## 定位

以 Laravel 和 Vue 为基础，为新业务项目提供可复制、可独立部署的后台模板。框架负责管理员身份、菜单、操作权限和审计。业务模块负责自己的数据模型、业务规则和记录级授权。

## 当前能力

| 能力 | 当前状态 |
| --- | --- |
| 管理员认证 | 已接通登录、当前账号查询和退出。登录有频率限制，停用账号或由管理者重置密码会撤销对应账号的 Token。 |
| 管理员与角色组 | 管理员和角色组页面已接通真实 API。角色组可以向下分配权限，子组权限受父组分配上限约束。 |
| 菜单与按钮权限 | 已实现并接通管理页：目录、菜单和按钮权限统一由 `/api/v1/admin/menus` 维护，当前管理员导航仍使用 `/api/v1/admin/me/menus`。创建、编辑、移动、启停、删除和删除影响预览均调用真实接口，变更后同步刷新管理树、导航和按钮权限。 |
| 审计日志 | 已记录登录、退出和系统管理写操作，支持按权限查询、筛选、分页、查看详情和定期清理。审计路由和字段目前针对内置模块定义。 |
| 前端共享组件 | 日志页已使用 `ArtSearchBar` 和 `ArtTable`。新增或改造列表时，优先复用共享组件及其列配置、分页和插槽。 |

现有接口、权限约定和维护命令见 [项目说明](README.md)。菜单树的数据模型和权限联动见 [菜单管理实施方案](MENU_MANAGEMENT_PLAN.md)。页面复用要求见 [后台页面规则](../.ai/rules/views.md)。

## P0 核心功能

### 菜单管理

状态：已完成。菜单管理页通过实际页面验证了保存后刷新持久化、删除前影响预览与确认、停用分支后导航同步移除；后端测试验证了无操作权限或无页面访问权时服务端拒绝写入，前端 `pnpm lint` 与 `pnpm build` 均通过。

菜单管理页接入 `/api/v1/admin/menus`，导航继续使用 `/api/v1/admin/me/menus`。使用 `ArtSearchBar` 和 `ArtTable` 展示并操作目录、菜单和按钮权限。表单沿用服务端对节点类型、父级和权限标识的限制。

- 创建、编辑、移动、启停及删除均调用真实接口。重新加载页面后能看到保存结果。
- 删除前展示影响预览并要求确认。后端拒绝删除时，显示实际原因。只有接口成功才提示操作成功。
- 当前操作者具备相应权限时才显示操作按钮。菜单更新后重新获取导航和按钮权限，停用分支后相应页面及 API 都受访问限制。

### 空库安装与升级

提供可重复执行的初始化流程，从空数据库完成迁移和系统菜单初始化。通过显式的命令行流程创建首个启用的 `super-admin` 账号，从隐藏输入读取初始密码。

- 按快速启动文档可从干净检出安装到首次登录，进入菜单、管理员、角色组和审计页面。
- 重新运行初始化时不会产生重复记录，也不会重置现有管理员、密码或权限分配。示例账号独立于安装流程。
- 验证已有数据库升级后仍保留原有账号、菜单标识和授权关系。

### 个人中心

个人中心读取当前管理员的真实资料，支持修改允许本人维护的字段。修改密码时校验当前密码并执行明确的 Token 撤销规则。后台默认通过管理员管理来创建账号，页面只展示已经接通的个人中心和认证功能。

- 资料保存后刷新页面仍能看到更新。
- 错误的当前密码无法修改密码。修改成功后，旧 Token 按约定失效，并可使用新密码重新登录。
- 日志只记密码已变更这一事实，响应和日志均不包含密码值。

## P1 模块扩展与交付

### 公告管理参考模块

用一套公告管理功能验证扩展约定。模块随代码注册菜单、页面访问和操作权限。前端复用 `ArtSearchBar`、`ArtTable`，API 沿用管理员鉴权、现有响应格式和服务端分页。需要审计的业务写操作显式声明动作、对象和允许记录的字段。

- 有权账号可以完成公告的筛选、分页、新建、编辑和删除。缺少操作权限的账号直接请求对应 API 时返回 `403`。
- 成功写入产生可查询的审计记录。日志与业务写入采用同一事务，只采集声明的字段。
- 开发者可按该模块的接入说明增加自己的页面、API、菜单权限和审计，无须改动内置菜单、管理员和角色组的业务代码。

### 持续集成与发布

在 CI 中运行 Laravel 测试和 Web 生产构建。把同一提交的 Laravel 代码和 `web/dist` 发布到测试环境，测试通过后再使用同一版本发布生产。生产环境通过同一域名提供 Vue 页面和 `/api`。

- 发布流程包含迁移、必要的系统菜单初始化、前端入口与 `/up` 健康检查，以及针对真实 API 的验证。
- 浏览器冒烟覆盖登录、菜单可见性、受权限限制的写入和审计详情。发布版本可追溯到 Git 提交。
- 部署时保留上一版产物，验证代码切回流程。数据库变更单独验证向后兼容性和恢复步骤。
- 生产环境保留自己的 `.env` 和 `APP_KEY`，配置 `schedule:run` 执行审计日志保留策略。

## 按业务需求扩展的边界

- **记录级授权**随真实业务模块验证。以地区订单为例，仅获授权的地区订单能够出现在列表、详情和导出结果中。现有角色组层级管理的是管理员与角色组的管理范围，业务记录范围由对应模块定义和检查。
- **租户隔离**在确有多个客户共用一套实例时单独设计，届时统一明确管理员身份、业务数据和审计记录的租户归属。

## 版本验收顺序

先从空库安装并登录，完成菜单管理和个人中心。再接入公告管理，使用不同权限的账号验证导航、API 访问、写入和审计。最后通过 CI 在测试环境部署和切回该版本，走完从新建项目到交付的流程。
